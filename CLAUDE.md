# Cloudify-Player

Кроссплатформенный десктопный клиент для SoundCloud с красивым UI, глубокой кастомизацией и синхронизацией пользовательского аккаунта (лайки, плейлисты, подписки, загрузки).

## Статус

Ранняя стадия. В приоритете — разведка API SoundCloud и настройка окружения.

## Целевые платформы

**Сейчас (P1):**
- Linux: `.AppImage`, `.deb`, `.rpm`
- Windows: `.exe` (installer + portable)

**Потом (P2):**
- Android: `.apk` для широкого распространения
- iOS: `.ipa` (self-signed, для личного использования)

**Когда-нибудь (P3):**
- macOS

**Не делаем:** веб-версия. Только нативные бинарники.

## Стек

- **Runtime:** Tauri 2 (Rust core + WebView frontend)
- **Frontend:** React 18 + TypeScript + Vite
- **Стилизация:** Tailwind CSS + shadcn/ui
- **State:** Zustand
- **Плеер:** Web Audio API (`howler.js` как обёртка, если понадобится HLS — `hls.js`)
- **Backend (Rust):** `reqwest` (HTTP), `tokio` (async), `keyring` (безопасное хранение токенов), `sqlx` + SQLite (локальный кэш)

**Почему Tauri, а не Electron:** бинарники 5–15 МБ вместо 150+ МБ, низкое потребление RAM (плеер часто висит фоном), нативная поддержка мобильных таргетов в Tauri 2.

## ⚠️ Критично: работа с API SoundCloud

**У проекта нет и не будет официального API-ключа.** SoundCloud закрыл регистрацию новых приложений в 2015 году.

**Что делаем:** используем внутренний API `api-v2.soundcloud.com` — тот же, что использует сам сайт soundcloud.com в браузере. Формально это серая зона, юридических рисков для open-source клиента минимальны, но SoundCloud может сломать нас сменой API в любой момент.

**Получение `client_id`:**
1. Скачиваем главную страницу `https://soundcloud.com`
2. Извлекаем URL всех JS-бандлов из HTML
3. Ищем в бандлах строку вида `client_id:"XXXXXXXX"`
4. Кэшируем; проверяем валидность раз в сутки; при 401/403 — перевытаскиваем автоматически

**Референс:** https://github.com/soundcloud-key-fetch — посмотреть подход, но копировать код только с учётом лицензии.

**Авторизация:** OAuth-поток через веб-логин (открываем окно с формой SC внутри приложения). Токен сохраняем в системный keyring, не в файле.

**Юридические оговорки в README и About:**
- "Неофициальный клиент. Не аффилирован с SoundCloud."
- "Используйте на свой страх и риск."
- Не публикуем в App Store / Play Store — только напрямую релизами на GitHub.

## Устойчивость к поломкам API

SoundCloud может сломать нас в любой момент. Известный клиент **Auryo** умер именно поэтому. Меры:

1. **Изоляция.** Весь код SC-API живёт в `src-tauri/src/sc_api/`. Никаких прямых обращений из UI.
2. **Абстракция.** Frontend вызывает только методы вроде `getUserLikes()`, не знает про URL.
3. **Логирование.** При ошибке API логируем запрос/ответ (без секретов) для диагностики.
4. **Feature flags.** Если поиск сломался — остальное продолжает работать. Не падаем всем приложением.
5. **Версионирование эндпоинтов.** У каждого метода есть версия; если появится fallback — просто добавим.

## Соглашения

- **Язык кода:** английский. Имена переменных, комментарии, коммиты — на английском.
- **Русский:** только в UI-строках, и то через i18n-словарь (`src/i18n/ru.json`), а не хардкод.
- **Коммиты:** conventional commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`).
- **TypeScript:** strict mode. Никаких `any` без комментария-объяснения.
- **Rust:** без варнингов `clippy`, `rustfmt` перед каждым коммитом.
- **UI-компоненты:** shadcn ставим через `pnpm dlx shadcn@latest add <name>`, не переписываем вручную. Кастомизируем через Tailwind-классы и CSS-переменные тем.

---

## Правила: чего НЕ делать

- ❌ Не хранить `client_id`, токены, пароли в коде или в plain-файлах. Только keyring / env.
- ❌ Не парсить HTML SoundCloud регулярками, кроме извлечения `client_id` из JS-бандла.
- ❌ Не использовать Electron, ни при каких обстоятельствах.
- ❌ Не тянуть тяжёлые UI-либы (MUI, Ant Design, Chakra). Только shadcn + Tailwind.
- ❌ Не запрашивать SC-API из React напрямую — всегда через Tauri command в Rust.
- ❌ Не логировать токены и заголовки авторизации.
- ❌ Не деплоить в App Store / Play Store.
